## 技能定位

`wechat-connect` — 让 Claude 在需要用户确认时，通过企业微信发送消息并等待回复，实现不在电脑旁也能参与决策。

**触发方式：Claude 自主判断。** 典型触发场景：
- 删除文件、force push 等不可逆操作前请求确认
- 长时间任务（>5分钟）完成后通知
- 遇到需要人工决策的歧义时询问
- 执行高风险命令前二次确认

**不触发：** 常规读写、git status、代码搜索等安全操作。

## 技术架构

推荐方案：**企业微信 API 发消息 + 回调 URL 收回复 + cloudflared 内网穿透**

```
发送路径: Claude → send.sh → curl → 企业微信 API → 用户微信
接收路径: 用户回复 → 企业微信回调 → cloudflared → wecom-server.py → replies.jsonl → Claude 读取
```

## 技能产出物

放在 `~/.claude/skills/wechat-connect/` 下：

```
~/.claude/skills/wechat-connect/
  SKILL.md              # Agent 使用说明
  config.example.json   # 配置文件模板
  send.sh               # 发送消息脚本 (curl)
  wait-reply.sh         # 等待回复脚本 (轮询 replies.jsonl)
  wecom-server.py       # 回调接收服务器 (Python 标准库)
  wecom-daemon.sh       # 守护进程：启动 server + cloudflared 隧道
```

## 各组件功能要求

### send.sh
- 从 `~/.claude/wechat-connect/config.json` 读取 corpid、agentid、secret
- 先调 `/cgi-bin/gettoken` 获取 access_token（缓存到 /tmp，过期自动刷新）
- 调 `/cgi-bin/message/send` 发送 text/markdown 消息
- 每条消息自动生成 `msg_id`（uuidgen 或 timestamp+random），写入 `pending_msgs.jsonl`
- 超时 10s，非 200 响应输出错误信息
- 支持参数：`--to-user <id>` `--message <text>` `--type text|markdown`

### wecom-server.py
- 仅用 Python 标准库（http.server），不依赖 flask/fastapi
- 监听 localhost:19800
- GET /wecom/callback → URL 验证（解密 echostr 并返回）
- POST /wecom/callback → 解密 XML 消息体，提取用户回复，写入 `replies.jsonl`
- 每条回复记录：`{msg_id, from_user, content, timestamp}`
- 日志写入 `~/.claude/wechat-connect/server.log`

### wait-reply.sh
- 轮询 `replies.jsonl`，按 `msg_id` 匹配回复
- 参数：`--msg-id <id>` `--timeout <seconds>`（默认 300s）
- 超时返回 exit code 1
- 收到回复后输出回复内容并返回 exit code 0
- 轮询间隔 5s

### wecom-daemon.sh
- 检查 cloudflared 是否安装（未安装则提示下载链接）
- 后台启动 wecom-server.py
- 后台启动 cloudflared tunnel，提取公网 URL
- 将公网 URL 输出并提示用户配置到企业微信后台
- 处理进程退出和重启

### config.json 格式
```json
{
  "corpid": "wwxxxxxxxxxxxx",
  "agentid": 1000002,
  "secret": "xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
  "default_user": "YourName",
  "callback_token": "随机字符串",
  "callback_aeskey": "43位随机字符串"
}
```

## benchmark 评估维度

创建完成后用 skill-benchmark 评估，输出报告即可，先不迭代。评估项：

| 维度 | 测试内容 | 判定标准 |
|---|---|---|
| S1: 配置缺失 | 无 config.json 时调 send.sh | 输出明确错误 + exit 1 |
| S2: API 发送 | 用有效凭证发送一条消息 | exit 0，企业微信收到消息 |
| S3: API 超时 | 模拟网络不可达 | 10s 内超时退出 + 输出超时信息 + exit 1 |
| S4: 无效用户 | 发送给不存在的 touser | 输出 API 错误码 + exit 1 |
| S5: 回调接收 | 启动 server，模拟企业微信回调请求 | 正确解密并写入 replies.jsonl |
| S6: 回复等待 | wait-reply.sh 等未到达的回复 → 超时 | exit 1，输出超时信息 |
| S7: SKILL.md 质量 | Claude 阅读 SKILL.md 后能否自主判断何时触发 | 给定 5 个场景，正确识别 4+ 个 |

## 范围边界

不做的：
- 不实现 OAuth 网页授权
- 不依赖 pip install 第三方包（server.py 仅标准库）
- 不自动修改企业微信后台配置（需用户手动配回调 URL）
- 不处理企业微信以外的 IM 渠道
